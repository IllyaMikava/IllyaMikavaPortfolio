MongoDB Hackathon · team of 4

InternMatch AI

Upload a CV once and get one email per strong internship match, each stating that role's next step.

  • Python
  • FastAPI
  • MongoDB
  • Atlas Vector Search
  • Voyage AI
  • Claude API
repo ↗
Details
Problem
Students search listings one by one, keyword filters miss roles that fit their skills in non-obvious ways, and recruiters' next steps stay unclear until late.
Data
271 hand-authored internship listings, embedded and stored in MongoDB Atlas.
Approach
CV text is extracted from PDF, DOCX or TXT and embedded with Voyage AI (voyage-3, 1024 dimensions), then matched against listings with Atlas $vectorSearch. Matches scoring at least 0.75 are kept, capped at five. Each one triggers an email with a short "why this matched" line from Claude, the role's next step verbatim, and the link.
Limits
Static dataset, no accounts or recruiter dashboard. The 0.75 threshold is a tuned default, not validated at scale.

Python desktop app

Rubik's Cube Solver

A PyQt6 app that solves any valid cube and explains each step in plain English.

  • Python
  • PyQt6
  • Kociemba
  • Gemini API
  • Groq API
repo ↗
Details
Problem
Photo-based cube input is unreliable, and solvers rarely explain their solutions.
Data
All 54 facelets of the cube, entered by the user.
Approach
Kociemba two-phase solver. A clickable 2D net where you paint each sticker removes photo input entirely. Gemini and Groq LLMs, used as a fallback chain, write the step-by-step explanations while the net animates every move.

Open source · C · bug fixing and optimisation

Minimax algorithm with Alpha-Beta Pruning

Fixing bugs and speeding up an open-source chess engine written in C, so its search is faster and more efficient.

  • C
  • SDL3
  • Minimax
  • Alpha-beta pruning
  • Move generation
  • Optimisation
repo ↗
Details
Origin
Not my engine: it is an existing open-source project that I am improving.
Engine
Legal move generation for all pieces, move validation, and an SDL3 GUI with mouse input. You can play Pass'n'Play or against a bot.
Approach
The bot searches a user-set depth of move pairs with alpha-beta pruning, scoring leaf positions on material, king safety and rooks on open files. My work is finding and fixing bugs and making the code faster and more efficient.
Limits
Work in progress, so there are no benchmark results to report yet.

Bot Detection on X

Scrapes a user's X page and uses an LLM as a judge to score whether the account is a bot, maybe a bot, or not a bot.

  • Python
  • PostgreSQL
  • FastAPI
  • LLM as judge
  • Fine-tuned model (planned)
Details
Status
Under development by a team of 5.
Pipeline
The app scrapes a user's X page and stores some of their comments in a PostgreSQL database. An LLM then acts as the judge and gives the account a score (bot, maybe bot or not bot) based on the profile information and the comments.
Next
A fine-tuned model is planned for the future.
Limits
Still in progress, so there are no accuracy results to report yet.
